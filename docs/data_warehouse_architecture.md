# 数据仓库分层架构设计

## 概述

本项目采用经典的数据仓库分层架构：ODS → DWD → DWS → ADS，确保数据处理的清晰性、可维护性和可扩展性。

## 分层架构

### 1. ODS层 (Operational Data Store)
**定位：** 原始数据层，保持数据原貌

**特点：**
- 直接从源系统同步的数据
- 不做任何修改，保持原始状态
- 作为数据仓库的数据源

**当前表结构：**
- `ods_loan_rejected`: 被拒绝的贷款申请数据
- `ods_loan_approved`: 被批准的贷款申请数据（如果存在）

**原则：**
- ❌ 不进行任何数据清洗
- ❌ 不修改原始数据
- ✅ 仅用于数据探查和质量分析

### 2. DWD层 (Data Warehouse Detail)
**定位：** 明细数据层，数据清洗和标准化

**目标：**
- 数据清洗：处理空值、异常值、重复数据
- 数据标准化：统一格式、单位、编码
- 数据验证：确保数据质量

**主要任务：**
1. **数据清洗**
   - 处理缺失值
   - 标准化数据格式
   - 清理异常值
   - 统一编码标准

2. **字段处理**
   - 百分比字段转换为数值（如 "15%" → 15.0）
   - 日期格式标准化
   - 金额字段类型转换
   - 分类字段编码

3. **数据验证**
   - 数据范围验证
   - 业务规则验证
   - 数据一致性检查

**输出表：**
- `dwd_loan_rejected_clean`: 清洗后的被拒绝贷款数据
- `dwd_loan_approved_clean`: 清洗后的被批准贷款数据

### 3. DWS层 (Data Warehouse Summary)
**定位：** 汇总数据层，面向主题的数据聚合

**目标：**
- 按业务主题进行数据汇总
- 提供常用的分析维度和指标
- 减少ADS层的计算压力

**主题域划分：**
1. **地理主题**
   - 按州、城市的贷款拒绝统计
   - 地理分布特征

2. **时间主题**
   - 按年、月、日的趋势分析
   - 季节性特征

3. **风险主题**
   - 风险等级分布
   - 风险评分统计

4. **客户主题**
   - 就业年限分布
   - 收入水平分析

5. **产品主题**
   - 贷款用途分析
   - 金额区间分布

**输出表：**
- `dws_loan_reject_geo`: 地理维度汇总
- `dws_loan_reject_time`: 时间维度汇总
- `dws_loan_reject_risk`: 风险维度汇总
- `dws_loan_reject_customer`: 客户维度汇总
- `dws_loan_reject_product`: 产品维度汇总

### 4. ADS层 (Application Data Store)
**定位：** 应用数据层，面向具体业务应用

**目标：**
- 为具体业务应用提供数据支持
- 高度优化的查询性能
- 业务友好的数据模型

**应用场景：**
1. **风控分析应用**
   - 风险评分分布
   - 拒绝原因分析
   - 风险趋势预测

2. **业务报表应用**
   - 月度拒绝统计报表
   - 地区业务分析报告
   - 产品表现分析

3. **机器学习应用**
   - 特征工程数据
   - 模型训练数据集
   - 预测结果数据

**输出表：**
- `ads_loan_risk_analysis`: 风控分析数据
- `ads_loan_business_report`: 业务报表数据
- `ads_loan_ml_features`: 机器学习特征数据

## 数据处理流程

### 整体流程
```
ODS层 (原始数据)
    ↓
DWD层 (数据清洗和标准化)
    ↓
DWS层 (面向主题的汇总)
    ↓
ADS层 (面向应用的数据)
```

### 具体实现步骤

#### 步骤1：ODS层数据探查
- 数据质量分析
- 数据结构理解
- 业务规则梳理

#### 步骤2：DWD层数据清洗
- 空值处理策略
- 数据格式标准化
- 异常值处理
- 数据验证

#### 步骤3：DWS层数据汇总
- 确定汇总维度
- 设计汇总指标
- 实现聚合逻辑

#### 步骤4：ADS层应用数据
- 设计应用数据模型
- 优化查询性能
- 提供业务接口

## 数据质量保障

### 质量维度
1. **完整性**：数据是否存在缺失
2. **准确性**：数据是否正确
3. **一致性**：数据格式是否统一
4. **及时性**：数据更新是否及时
5. **唯一性**：是否存在重复数据

### 质量控制措施
- 建立数据质量监控体系
- 定期进行数据质量评估
- 建立数据质量改进机制
